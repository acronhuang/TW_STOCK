# 決策支援價值的載體是 `portfolio_lots`，不是 `portfolio_trades`

[ADR-0015](0015-交易紀錄標記是否來自系統建議.md) 決定在 `portfolio_trades` 上加
`from_system` 布林值，以支撐 [ADR-0014](0014-系統成功的判準.md) 的輔助判準
「系統推薦的表現有沒有比自己找的好」。實際查證推翻了它的兩個前提：

**一、那 17 筆不是交易，是一次期初建倉快照。**
16/17 筆的 `note` 是「XXX 現有持股」，全部同一天（2026-04-15）。
它們既不是「因系統建議而買」也不是「自己找的」，而是「系統開始記錄之前就持有」——
沒有可回填的決策。

**二、記錄介面早就存在，只是寫的不是那張表。**
`dashboard/pages/risk_page.py` 有完整的可編輯表格（代號／買進日／股數／價格／分類／備註，
可新增可刪除），它寫的是 `portfolio_lots`；而 `src/portfolio/tracker.py` 的 `__main__`
只是測試 demo，不是可用的 CLI。

~~`portfolio_trades` 停更四個月，很可能正是因為它沒有介面。~~
**此推論有誤（2026-08-17 更正）**：`portfolio_lots` **有**介面，卻同樣沒有任何 `trade` 紀錄——
「沒有介面」解釋不了這個現象。真正的原因見下方「為什麼決策筆數這麼少」。

決定：**載體改為 `portfolio_lots`**，並新增兩個欄位。

| 欄位 | 值 | 說明 |
|---|---|---|
| `kind` | `trade` / `opening_balance` / `allocation` | 這筆部位**反映了誰的判斷**：我的決策／系統存在前的我／沒有人（2026-08-17 由二態擴為三態） |
| `from_system` | `true` / `false` / `None` | 是否因系統建議而買；**只對 `kind=trade` 有意義**，`opening_balance` 一律 `None` |

不採用「`from_system` 三態」的理由：那會讓「不適用」與「還沒填」都是 `None`，
而 [ADR-0002](0002-檢查的有效性條件.md) 的精神正是「無資料」必須與「已判定」區分開。

## Consequences

- `portfolio_lots` 的資料品質本就優於 `portfolio_trades`：`buy_date` 是 datetime
  （符合 README 的命名規範），而 `portfolio_trades.date` 存字串、違反規範。
  換載體因此順帶消解了「要不要遷移那 17 筆字串日期」的問題——不必動一張即將棄用的表。
- `risk_page` 的編輯表格加上「期初持倉」與「來自系統建議」兩個勾選欄，
  順著既有動線，不新增工具、不產生兩套並行的記錄方式。
- 既有 17 筆的分類（2026-08-17 修正）：**15 筆 `opening_balance` + 2 筆 `trade`**。

## 為什麼決策筆數這麼少（2026-08-17 查證）

|  |  |
|---|---|
| 系統首個分析日 | 2026-04-15 |
| 系統首個合議定案 | **2026-06-19** |
| 17 筆持倉的買進日 | 2023-03 ~ 2026-07，橫跨 3 年半 |
| 買在系統首個分析日之前 | **15 筆** |

**「決策筆數趨近於零」的原因是系統太年輕，不是漏記、也不是沒有介面。**
15/17 的持倉買在系統存在之前，它們在定義上不可能來自系統建議。

🔴 **一併修正一個錯誤的回填**：初次回填以「`note` 含既有持倉／現有持股／期初」為判準，
17 筆全數命中——但那是因為遷移腳本對**所有列**寫了同一句 note，
用一個「全部都一樣」的欄位當判準等於沒有判準。實際上有 2 筆買在系統開始分析之後：

| 標的 | 買進日 | 判定 | 依據 |
|---|---|---|---|
| `6884` 海柏特 | 2026-06-17 | `trade` / `from_system=false` | 早於系統首個合議定案 2026-06-19，當時系統尚未給過本檔任何定案 |
| `1586` 和勤 | 2026-07-20 | `trade` / `from_system=false` | 買進前最近兩次定案（07-17、07-10）皆為「持有」，系統未建議買進 |

兩筆的判定依據已寫入各自的 `note`，可追溯、可推翻。它們是 [ADR-0014](0014-系統成功的判準.md)
輔助判準「自己找的」那一組的頭兩個樣本——**輔助判準因此不再是零樣本**。

`from_system=false`（有依據的判定）與 `None`（不適用）語意不同，這正是
[ADR-0002](0002-檢查的有效性條件.md)「無資料必須與已判定區分開」在資料層的體現。
- `portfolio_trades` 就此成為歷史表，不再維護，也不需要加 `from_system`。

## 2026-08-17 收尾 —— 刪 `tracker.py`，但**保留** `portfolio_trades`

`src/portfolio/tracker.py`（669 行）是 `portfolio_trades` 的唯一寫入者。它不是死碼：
`live_advisor` 有 5 處 import，`src/portfolio/__init__.py` 會把它拉進來（所以連風控頁
都間接載入它），還有 3 支 BDD 測試在 regression gate 裡跑它。故順序是
**先移除依賴、把測試改指向現役元件，最後才刪檔**。

- `live_advisor` 的 `COLLECTION` 改為模組常數 `POSITIONS`；`execute()` 整段移除——
  它透過 tracker 寫已凍結的 `portfolio_trades`，且需 `confirm=True`、從未被呼叫。
  「照系統建議買進」的記錄路徑是風控頁的 `from_system` 勾選欄，已存在且在用。
- BDD 的三個情境（買入登記／投組摘要／多次加碼平均成本）描述的行為現在由
  `lots.py` 實作，**feature 檔一字未改**，只換步驟定義指向的元件。
  🔴 順帶補一層保護：`replace_lots` 是 `delete_many({})` 全刪重寫、**沒有投組名稱過濾**，
  在 production DB 上跑會清掉真實持倉。故改用獨立測試 DB —— 原本 tracker 版靠
  `portfolio` 欄位過濾共用同一個 DB，換元件後那層保護就不存在了。

**表則保留。** 刪表 SOP 第 3 步（是否為他表的真子集）擋下了刪除：

| `portfolio_trades` 獨有的資訊 | 為什麼不能丟 |
|---|---|
| `1108` 幸福 27000@14.80、`2892` 第一金 4000@28.70 | 兩檔**已賣出**持倉的唯一紀錄，`portfolio_lots` 沒有 |
| `commission` / `cost` / `total` | 手續費，`portfolio_lots` 完全沒有這三欄 |
| 2026-04-12~15 的價格快照 | 15 檔與現在的均價都不同（加買合併前的值） |

「已退役」不等於「可刪」。退役的是**寫入者**，不是那份資料。

## 2026-08-17 再修正 —— `kind` 擴為三態

使用者說明兩筆的實際來源後，二態不夠用：

- **`6884` 海柏特：公司配的。** 它既不是買進決策（`trade`），也不符合「系統開始記錄
  **之前**就持有」（`opening_balance`，而它買在 2026-06-17，系統之後）。
  把它算成「自己找的」會**污染對照基準**——公司配股的報酬與選股能力無關。
  故新增 `allocation`：公司配股／員工認股／配息再投資等，**沒有任何人的判斷**。
- **`1586` 和勤：看可以買就買的。** 確認為 `trade` / `from_system=false`。
  使用者的陳述與定案紀錄互相印證：買進前最近兩次定案（07-17、07-10）皆為「持有」，
  系統未建議買進——兩條獨立證據指向同一結論。

`kind` 真正回答的問題因此是「**這筆部位反映了誰的判斷**」：

| 值 | 反映誰的判斷 | 計入決策支援價值？ |
|---|---|---|
| `trade` | 我 | ✅（`from_system` 再分兩組） |
| `opening_balance` | 系統存在之前的我 | ❌ |
| `allocation` | 沒有人 | ❌ |

**輔助判準的樣本因此從 2 退回 1**（只剩 `1586`，屬「自己找的」那組）。
這是誠實的 1——虛胖的 2 會讓對照組混入一筆與判斷無關的部位。

UI 也隨之改變：`risk_page` 的「期初持倉」勾選框無法表達三態，改為「取得方式」下拉選單。
