# 系統成功的判準：判斷品質為主、決策支援價值為輔，明確不採用實際績效

ADR-0001 至 0013 全部在談「實作對不對」——檢查是否有效、量尺是否正確、資料是否完整。
但沒有任何一條回答「做對了又如何」。實測顯示這個缺口是真的：

| | |
|---|---|
| 系統曾判「買進」的標的 | **574 檔** |
| 實際持倉 | 17 檔，其中曾被系統判買進的 **8 檔** |
| `portfolio_trades` | 17 筆，全部集中在 **2026-04-12 ~ 04-15**，之後無新紀錄 |

`NFR-QUAL-001/002` 量的是合議定案的超額報酬，那是**判斷的品質**；
它回答不了「這個系統值不值得每晚燒 GPU 跑三天」。

決定：

- **(a) 判斷品質為主**（現況的 NFR-QUAL-001/002）——保留為自動化的品質底線，
  它至少能抓到「系統壞掉了」。
- **(c) 決策支援價值為輔**——量測「系統判買進且實際買進」的標的，事後表現是否優於
  「自己找的」標的。這才是系統存在的理由。
- **(b) 實際績效（持倉報酬 vs 大盤）明確不採用**——它把系統價值與執行綁在一起：
  若某季無暇看盤，系統會「看起來變差」，那是錯誤訊號。且樣本僅 17 檔、17 筆交易，
  統計上得不出結論。

## 輔助判準的已知限制（2026-08-17 補）

**(c) 決策支援價值目前還不能算，而且不是因為程式沒寫。**

`portfolio_lots` 一直只記買進：三張持倉表全表只有 `BUY`，賣出從來沒被記錄過。
`tracker.py` 有完整的 `sell()`（寫 `action=SELL`、算已實現損益），但它寫的是
已退役的 `portfolio_trades`，且從未被呼叫；搬到 `portfolio_lots` 時賣出路徑
沒有跟著搬。

賣掉的部位直接從資料中消失，會造成**存活者偏誤**——只看得到還留著的，
賣掉的（停損的、停利的）全不見。這種偏誤看不出來，因為剩下的每一筆數字都是對的。

處置：`portfolio_lots` 加 `sell_date` / `sell_price`，**賣出時標記而非刪列**。
已賣出者不計入持倉，但永久留在表裡供事後對照。

**仍然無法補救的部分（算這個判準時必須一起報出來）：**

1. **2026-08-17 之前的賣出永久遺失。** 已知至少 1108 幸福、2892 第一金
   賣掉後無紀錄，賣出日與賣出價已無從查證，**不回填**——承認遺失比填假的好。
2. **樣本量太小。** 17 檔中只有 1 檔（1586 和勤）是系統存在後做的買進決策，
   且是「自己找的」。「系統推薦且照做」目前 **0 筆**，對照組還不存在。
3. **舊的 15 筆是均價不是單次買進**，加買已被合併。若某次加買照系統建議、
   另一次不是，事後無法分辨。

因此這個判準要等新資料累積，而不是「已經在算只是數字不好看」。
在有雙向樣本（系統推薦照做 vs 自己找的）各達到可比較的數量之前，
**不得輸出這個判準的數值** —— 單邊樣本算出來的差距沒有意義。

## Consequences

- **`portfolio_trades` 停更四個月，成為最高優先的資料缺口。** 沒有它，(c) 永遠算不出來——
  這比 2026-08-15 整夜修的任何項目都重要，而當晚一次都沒提到它。
  （2026-08-16 已確認將恢復維護，見 [ADR-0015](0015-交易紀錄標記是否來自系統建議.md)。）
- (a) 與 (c) 回答不同問題，不可互相取代：574 個買進判斷若只有 8 個被採納，
  另外 566 個的準確度對使用者沒有價值——(a) 高分不蘊含 (c) 高分。
- 「曾被系統判買進」與「因系統建議而買」不是同一件事，目前只能以 symbol 粗略比對。
  要正確量測 (c)，交易紀錄需能連結到當時的建議——見後續 ADR。
