# v5 上線簽核與問責機制(governance)

> 目的:讓「改變真錢交易依據的 live verdict」有**具名問責、可稽核、可回滾**。
> 全程對照已建工具:`buyside_validate_v5`(Go/No-Go)、`verdict_sli`(上線後監看)。

---

## A. 角色(上線前指定,具名)
| 角色 | 職責 | 由誰 |
|---|---|---|
| 技術覆核者 | 確認方法/閘門/OOS/去噪正確 | ______(簽名/日期)|
| **風險問責者** | **承擔 live 改動 P&L 後果**、拍板上線 | ______(簽名/日期)|

> 風險問責者**必須是一個人**(非「團隊」)。沒有具名問責者 → 不上線。

## B. 簽核前置閘門(全部 ✅ 才可簽)
- [ ] `buyside_validate_v5`(全量或足量樣本)**Go/No-Go = GO**
- [ ] ① 整體 v5 買進超額 > live(命中**且**均超額)
- [ ] ② **前後時間段皆超額改善**(OOS 一致,非單窗)
- [ ] ③ 樣本足夠(建議 n≥200;各時間段各半)
- [ ] ④ LLM 去噪(repeats≥3 取眾數,飄動率低)
- [ ] ⑤ 盤整未受影響(降級=0)
- [ ] 已閱讀**反方證據**:v4 曾 in-sample +2.90pp 卻 OOS 崩(超額惡化)
- [ ] 已閱讀**已知侷限**:in-sample 區間、LLM 非決定論、小型股特徵稀疏

## C. 決策紀錄(簽核=留下這一筆,進版控)
```
決議編號:V5-GO-<YYYYMMDD>
批准版本:git <hash>(scripts/buyside_shadow_advisor_v5.py + advisor_v5.py)
依據證據:logs/v5_validate_*.log(Go/No-Go 全文貼附)
技術覆核:<姓名> <日期>
風險問責:<姓名> <日期>
灰度範圍:先 __ % / __ 檔;監看窗 __ 天
回滾條件(事先同意,任一觸發即關 flag):
  - live 買方超額 < shadow 承諾值 − __ pp(連續 __ 日)
  - verdict_sli 未達標且較 baseline 惡化
  - 任何 live 異常(覆蓋驟降/評級全飄)
回滾方式:feature-flag 關閉(秒級生效,無需部署)
```

## D. 灰度上線(授權的是這個,不是全開)
1. feature-flag `BUYSIDE_V5_ENABLED`(**預設 off**)。
2. on 後,`team_analyze` 在**趨勢市**用 `build_advisor_prompt_v5` 包裝 advisor prompt(盤整不套)。
3. 先小量(如核心池/單一市況)→ 監看窗 → 擴大 → 全量。
4. **kill-switch**:關 flag 即回原行為,秒級、免部署、免回滾 commit。

## E. 上線後問責(不結束)
- 每日 `verdict_sli`(已分市況)比對:**live 是否複製 shadow 的改善**。
- shadow 承諾 vs live 實現落差 > 門檻 → **自動告警 + 觸發 C 的回滾條件**。
- 問責者定期覆核(如每週),直到穩定。

---

## F. 為什麼要這麼做(而非口頭 OK)
- live verdict = **真錢依據**;改它必須有人**具名擔後果**。
- v4 教訓:**看起來好 ≠ 真的好**;書面閘門擋住「憑感覺上線」。
- 可稽核紀錄:日後出事能追「誰、依據什麼、同意什麼回滾」——這是**問責的實體**。
- 秒級 kill-switch:讓「上線」變成**可逆**的決定,降低問責者的心理與實際風險。

> 一句話:**具名兩簽 + 前置閘門全過 + 書面回滾條件 + 秒級 flag** = 「有問責的人」的具體形態。
> 缺任一 → 不上線。
