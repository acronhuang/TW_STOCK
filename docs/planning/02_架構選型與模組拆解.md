# 架構選型分析與模組拆解 — 依環境與技能樹

> 你的技能樹/環境（實測）：Python 3.11–3.13、FastAPI、Streamlit、MongoDB(~65 集合)、
> 本地 Ollama(qwen2.5-14b)、FinMind、pytest/ruff。偏好純標準庫 + requests、fail-open、繁中文件。
> 選型以「不引入重量級新依賴、可離線單元測試、與既有 MoE/RAG 一致」為約束。

## A. 架構選型（3 案比較）

| 準則 | 方案 A：現況內嵌式(regex+requests) | 方案 B：抽象 Provider + 快取層 | 方案 C：非同步佇列 + 背景抓取 |
|---|---|---|---|
| 核心 | RSS 直解、同步呼叫 | `NewsProvider` 介面 + TTL 快取(記憶體/Mongo) | Celery/APScheduler 週期抓取入庫，UI 只讀 |
| 契合技能樹 | ★★★★★（零新依賴） | ★★★★（+1 快取抽象，仍純 py） | ★★（引入排程/佇列，維運重） |
| 外部穩定性 | 低（每次即時打 RSS） | 中高（快取吸收抖動、可退避） | 高（UI 不直連外網） |
| 即時性 | 高 | 高（TTL 內） | 低（依抓取週期） |
| 測試性 | 高（mock requests） | 高（mock provider） | 中（需 mock 佇列/排程） |
| 開發成本 | 0（已完成） | +1 人日 | +3~4 人日 |
| 合規/風控 | 弱 | 中（可加來源白名單/條款控管） | 中 |
| **建議** | 立即可上線基線 | **✅ 推薦：最佳性價比** | 過度設計，暫緩 |

**結論**：以 **方案 A 為交付基線**，**演進到方案 B**（新增 `NewsProvider` 介面 + TTL 快取 + 退避重試 + 來源白名單），把文件 1 的三大風險降到可接受。方案 C 待流量/合規需求明確再議。

## B. 目標架構（方案 B）分層
```
rag_page (UI)                      ── 只依賴介面，不知 RSS 細節
  └─ NewsService                   ── 聚合、去重、needs_supplement 決策
       ├─ NewsProvider (介面)
       │    └─ GoogleNewsRSSProvider(現況 google_news_search 內化)
       ├─ NewsCache (TTL, 記憶體→可換 Mongo)
       └─ Backoff/RateLimiter
  └─ InternationalAnalyzer         ── build_prompt + Ollama + 輸出後過濾
       └─ EvidenceGuard            ── 驗證輸出僅引用 [n] 且不含未列標的
```

## C. 模組拆解與驗收標準（Definition of Done）

### M1 `GoogleNewsRSSProvider`（重構自現況）
- 規格：輸入 query/region/max_items，輸出 `[{title,url,published_at,source}]`；去重(by url)；fail-open。
- 驗收：
  - AC1 成功解析 title/url/pubDate，`source` 含地區標籤（已測 ✅）。
  - AC2 `requests` 例外→回 `[]`，不拋出（已測 ✅）。
  - AC3 相同 url 只保留第一筆（已測 ✅，本次 TDD 新增）。
  - AC4 英文模式帶入 Reuters/Bloomberg/CNBC/FT site 過濾與 en-US feed（已測 ✅）。

### M2 `NewsCache`（新增，方案 B）
- 規格：key=(query,region)，TTL 預設 600s；命中回快取、未命中呼叫 provider 後寫入。
- 驗收：
  - AC1 TTL 內第二次呼叫**不觸發** requests（mock 斷言呼叫次數=1）。
  - AC2 TTL 過期後重新抓取。
  - AC3 快取失效/例外時退回直接抓取（fail-open）。

### M3 `Backoff/RateLimiter`（新增）
- 規格：連續失敗指數退避（0.5→1→2s，上限 3 次）；每分鐘上限 N 次。
- 驗收：
  - AC1 連續 429/例外時重試次數與間隔符合設定（用假時鐘測）。
  - AC2 超過每分鐘上限直接回空並記錄一次警告。

### M4 `search_news_by_mode`（沿用+接快取）
- 驗收：
  - AC1 綜合模式分組順序固定、各來源獨立（已測 ✅）。
  - AC2 「所有來源」列出五地區且順序穩定（已測 ✅）。
  - AC3 每地區走 M2 快取。

### M5 `EvidenceGuard`（新增，緩解風險#1）
- 規格：解析 LLM 輸出，若出現未在證據清單的股票代號/公司，或缺 `[n]` 引用，標記並降級顯示警語。
- 驗收：
  - AC1 輸出含未列台股標的→回傳 `flagged=True` 並附原因。
  - AC2 每段落至少一個 `[n]`，否則標記。
  - AC3 風險段落第一句固定含 `新聞僅為標題…[1]`（SYSTEM 已測 ✅）。

### M6 `generate_analysis`（沿用+逾時/降級）
- 驗收：
  - AC1 `articles` 空→不呼叫模型、回固定訊息與 0.0（實作已具，補測試）。
  - AC2 逾時/連線錯誤→上層 catch 顯示失敗訊息，本機結果不受影響。

### M7 `rag_page.show`（UI 整合）
- 驗收（對應 E2E）：
  - AC1 本機檢索段落正常呈現（E2E `01`）。
  - AC2 網路補充僅在 `needs_web_supplement` 為真時出現，且 fail-open（E2E `02`）。
  - AC3 國際分析顯示免責「不是投資建議」與證據編號（E2E `03`）。
  - AC4 空問題按分析→提醒，不呼叫外部（E2E `04`）。
