## 8. 時序圖 — 一次完整「團隊分析」呼叫順序
> 進入點 `scripts/team_daily_verified.py`（cron 或 CLI）；6 角色並行 → 守門過濾 → 顧問整合 → 合議定案 → 寫回 `team_analysis`。
```mermaid
sequenceDiagram
    autonumber
    participant CRON as cron / CLI
    participant TDV as team_daily_verified
    participant RR as role_router.ask_role
    participant OL27 as Ollama .27
    participant OL28 as Ollama .28
    participant G as moe/guard
    participant CONS as consensus.discuss
    participant TS as team_store
    participant DB as MongoDB team_analysis

    CRON->>TDV: 執行團隊分析(symbols)
    loop 每個標的 symbol
        par 6 角色並行 (Phase1, timeout 300s)
            TDV->>RR: ask_role(technical-analyst)
            RR->>OL27: llama3.1:8b generate
            OL27-->>RR: 技術分析
        and
            TDV->>RR: ask_role(fundamental/macro/value/chip/risk)
            RR->>OL28: qwen3-14b / gemma2 generate
            OL28-->>RR: 各角色報告
        end
        RR-->>TDV: reports{role: text | 分析失敗:…}
        TDV->>G: usable_reports(reports)
        G-->>TDV: 只留可用報告（失敗剔除）
        alt 全部失敗
            TDV-->>TDV: 略過整合（不以錯誤訊息決策）
        else 有可用報告
            TDV->>RR: ask_role(investment-advisor)
            RR->>OL28: qwen3-14b 整合 (timeout 600s)
            OL28-->>TDV: 顧問草案
            TDV->>CONS: discuss(symbol, 草案, 證據, rounds=2)
            loop 2 輪序列討論
                CONS->>OL27: 委員 qwen2.5-14b/llama3.1 投票
                CONS->>OL28: 委員 gemma2 投票
                OL27-->>CONS: 票+理由
                OL28-->>CONS: 票+理由
            end
            CONS->>OL28: 主持人 qwen3-14b 綜合定案
            OL28-->>CONS: final verdict
            CONS-->>TDV: {votes, tally, final, facilitator}
        end
        TDV->>TS: upsert_analyses(analysis)
        TS->>DB: upsert team_analysis（逐文件，不整份覆寫）
        TDV->>TDV: save_results() → results/team_analysis/*.json（雙寫）
    end
    Note over TDV,DB: 任何失敗 → schedule_alerts + LINE 通知；verify_committee 把關委員出席
```

## 9. 災難復原 / 備份流程
```mermaid
flowchart TB
  subgraph BK["🗄️ 備份機制"]
    direction TB
    B1["backup_mongodb.sh<br/>每週日 01:00 cron"] -->|mongodump| B2[("~/Stock/mongodb_backups/<br/>tw_stock_analysis_&lt;ts&gt;")]
    B2 --> B3["保留 30 天<br/>自動清理逾期備份"]
    G1["git backup/pre-*<br/>分支 + bundle"] --> G2["程式碼回滾點"]
  end
  subgraph DR["♻️ 復原路徑（依故障類型）"]
    direction TB
    R0{"故障類型?"}
    R0 -->|"資料損毀/誤刪"| RD["restore_mongodb.sh<br/>mongorestore 指定備份"]
    R0 -->|"部署故障"| RC["git reset --hard backup 分支<br/>(保留 stockrag patch) + restart"]
    R0 -->|"服務崩潰"| RS["systemd Restart=on-failure<br/>自動拉起"]
    R0 -->|"GPU 節點失聯"| RG["MoE fail-open:失敗角色剔除<br/>+ 委員棄權守門; 本機檢索不受影響"]
  end
  V["✅ 驗證:pytest 174 + API/Dashboard 健康檢查 + cron log"]
  B2 -.災難時.-> RD --> V
  G2 -.回滾.-> RC --> V
  RS --> V
  RG --> V
```
> **復原時間目標**：服務崩潰 systemd 自動拉起（秒級）；部署回滾 git reset + restart（分鐘級）；
> 資料復原 mongorestore（依資料量，數分鐘~數十分鐘）。**備份缺口**：目前每週備份，
> 週間資料損毀最多損失 ~7 天 —— 建議評估**每日 mongodump** 或 replica set（Phase 3+）。
